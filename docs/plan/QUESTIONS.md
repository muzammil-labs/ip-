Width migration happens screen by screen as each is rebuilt in Phase 4 to the new design; Shell.tsx has a comment noting this.

## Phase 3

- **UI-3.6 MSW's browser worker chunk is on the critical path in every environment, and it is large (~97KB gzip).** The task is explicit: "Start the worker in main.tsx before rendering (all environments, since there is no real backend yet)," so `main.tsx` awaits `worker.start()` before the first `render()` call. Vite still code-splits `src/api/mock/browser.ts` into its own chunk (dynamic `import()`), so the main entry chunk itself stays at 187KB gzip, under the Part E 200KB budget, but the mock worker chunk still has to download, parse and register before the user sees anything, which real users of the eventual production build (once a real backend exists and MSW is removed) will never pay. Worth re-measuring actual time-to-first-render once Lighthouse is wired up in Phase 7, and considering whether MSW should be gated behind an env check (`import.meta.env.DEV` or a build flag) rather than always-on, if the demo's real backend lands before finals. For now this matches the task's literal instruction.
