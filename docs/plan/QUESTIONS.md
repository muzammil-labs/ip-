Re-verified both call sites directly in a headless browser after the fix: `#/case/describe?c=test123` now keeps the query on navigation, and `#/ask?mode=kisan` now renders Kisan mode instead of the 404 page. - **UI-5.5's four Kisan-mode entry cards ("I grow", "I collect from forest", "I sell to a company", "Our area's produce is famous") are new, plain descriptive Hindi sentences written to trigger the real scripted corpus, not new legal content.** Per D0, only a legal reviewer writes legal statements/citations/rules; these are user-question phrasings, the same category as the existing suggestion-chip text elsewhere in the app. Two ("I grow", "I sell to a company") share enough keywords with the existing farmer answer (`q4`, already-vetted content on cultivation, sale, BMC origin certificates, farmers' variety and GI) to match it for real, cited answers. - **UI-5.3 accessibility pass found and fixed four real, verified violations, not just wired up the check.** `@axe-core/playwright` now runs inside `npm run shots` on every route in both themes (light/dark) and both sizes (1440/390), failing the run on any serious/critical violation. It caught: (1) `aria-prohibited-attr` on `EvidenceRow`'s state-mark span and `ChapterRail`'s evidence-spine column — a plain `<div>`/`<span>` defaults to ARIA role "generic", which does not permit `aria-label`; fixed by adding `role="img"` and `role="group"` respectively. (2) `button-name` (critical) on `Button`'s `loading` state — the dots-only spinner replaced the button's text entirely, leaving no accessible name while loading; fixed by keeping the label in an `sr-only` span alongside the dots. (3) `scrollable-region-focusable` on the API contract table in How it works — a horizontally-scrollable `<div>` with no way for a keyboard user to reach it; fixed with `tabIndex={0}` and `role="region"`; `DataTable`'s own table wrapper got the same `tabIndex={0}` pre-emptively. The keyboard walk and the 200% zoom check (simulated as a 640px viewport, the CSS-pixel-equivalent of 200% on a 1280px device, since Playwright has no direct "browser zoom" API) also caught a real bug: Describe's formula-builder grid (`sm:grid-cols-[2fr_1.5fr_1fr_auto]`) doesn't shrink below its columns' min-content width, overflowing the viewport by ~36px right at the `sm` (640px) breakpoint; fixed with `minmax(0, ...)` on each `fr` track, the standard CSS Grid fix (verified this doesn't hit the UI-0.1 comma bug: Tailwind's arbitrary-value parser only splits on top-level commas, not ones nested inside a function's parens, confirmed by checking the generated CSS has one `grid-template-columns` rule, not two classes).
- **UI-5.2 PWA and MSW share one service worker, on purpose.** `vite-plugin-pwa` (injectManifest strategy) builds `src/sw.ts` into `dist/sw.js`, which both precaches the app shell (Workbox) and `importScripts("./mockServiceWorker.js")` to pull MSW's own generated worker logic into the same instance. Registering two separate service workers at the same scope ("/") was ruled out: only one worker can control a scope, so whichever registered second would eventually take over and silently stop the other (MSW's API mocking has no real backend behind it, so losing it would break the whole app). `injectRegister: false` on the plugin, and `main.tsx` points MSW's own `worker.start({ serviceWorker: { url } })` at `sw.js` in a build (still at `mockServiceWorker.js` directly in dev, where the PWA worker doesn't exist, so dev behaviour is unchanged). Verified directly, not just claimed: built the app, loaded it once, confirmed the SW reached `activated` state, confirmed `/v1/sources` still returns real mocked JSON through it, then set the browser context offline and reloaded — the app rendered with no network, no console errors. A generated PNG icon set (`public/icons/`, rasterized once from a static SVG matching `ui/Seal.tsx`'s filled variant via a temporary `sharp` devDependency, removed after generating the files) also supplied `apple-touch-icon.png` and a real favicon, incidentally clearing the favicon-404 console entry that had shown up in every `npm run shots` run since Phase 0.
